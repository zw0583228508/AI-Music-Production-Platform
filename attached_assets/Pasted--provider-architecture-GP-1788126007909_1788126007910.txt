מהשלב הזה אני רוצה לשנות את סדר העדיפויות של הפיתוח.

התשתית הכללית, ה-provider architecture, ה-GPU orchestration, ה-jobs, ה-versioning וה-lineage כבר מספיק מתקדמים. כרגע לא להתמקד בעוד abstractions, עוד contracts, עוד מסכי UI או עוד infrastructure שאינה נדרשת ישירות ליצירת מוזיקה אמיתית.

המטרה המרכזית עכשיו היא להגיע מהר ככל האפשר ל-End-to-End production flow אמיתי שבו משתמש מעלה ווקאל או שיר, המערכת מנתחת אותו, בונה SongModel, יוצרת ArrangementPlan, מפיקה accompaniment אמיתי במודל GPU, מחזירה את התוצאה ל-Studio ומאפשרת Export.

לבנות לפי הסדר הבא:

1. להשלים קודם כל Flow מלא עם ACE-Step 1.5 שכבר עבר GPU smoke.

ה-flow חייב להיות:

Upload audio/vocal
→ preprocess
→ analysis
→ SongModel
→ StyleSpec
→ ArrangementPlan
→ ACE-Step provider
→ Modal GPU inference
→ generated accompaniment WAV
→ artifact registration
→ חזרה ל-project
→ playback בתוך Studio
→ export WAV

לא להסתפק ב-smoke test. להעביר שיר אמיתי דרך כל המערכת מתחילתה ועד סופה.

2. לבנות ACE-Step Production Integration מלאה.

לממש בפועל:

* COMPLETE
* LEGO
* REPAINT
* COVER
* EXTRACT

לכל operation לבנות request schema קבוע, seed, model version, prompt/style parameters, source artifact references, output artifacts ו-lineage.

ב-LEGO לאפשר יצירה של track בודד:

* drums
* bass
* piano
* guitar
* strings
* brass
* synth
* percussion
* FX

ב-REPAINT לאפשר:

* בחירת אזור לפי bar/beat/time
* regenerate רק את האזור
* crossfade תקין
* שמירת version חדש

3. להפעיל BS-RoFormer בפועל.

לא להמשיך עד שיש:

לתמוך בשינויי tempo ובשינויי meter לאורך השיר.

5. להפעיל MT3 בפועל.

לשמור notes, timing, velocity, program/instrument mapping ו-confidence.

לבנות normalization layer שמנקה:

* octave jumps

* timing noise
* impossible ranges
